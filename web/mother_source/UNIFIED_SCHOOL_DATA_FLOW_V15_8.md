# فراهوش — جریان یکپارچه اطلاعات مدرسه

از این نسخه، ثبت داده در هر پنل به‌صورت یک «رویداد مدرسه» قابل دریافت برای مقصدهای مجاز است.

## مقصدها
- فرد/دانش‌آموز و اولیای مرتبط
- کلاس
- نقش/گروه
- کل مدرسه

## نمونه‌ها
- نمره → دانش‌آموز + اولیای مرتبط + پرونده‌های مجاز آموزشی
- تکلیف → دانش‌آموز/کلاس + اولیا
- حضور و غیاب → دانش‌آموز + اولیا + پرونده‌های مجاز
- تشویق/انضباط → دانش‌آموز + اولیا + پرونده‌های مجاز پرورشی
- کارنامه، مشاوره، ارجاع، جلسه، ثبت‌نام مسابقه و تراکنش مالی دانش‌آموز → مخاطبان مرتبط
- مسابقه، جشنواره، برنامه امتحان، برنامه هفتگی و اطلاعیه مدرسه → مخاطبان مدرسه/گروه طبق مقصد

## وضعیت دریافت
هر رویداد و هر پیام می‌تواند وضعیت زیر را داشته باشد:
- در انتظار دریافت
- دریافت شد
- دیده شد

فرستنده از `sender_delivery(event_id)` یا `message_delivery_status(message_id)` می‌تواند وضعیت هر گیرنده مجاز را ببیند.

## اصل معماری
یک داده در منبع اصلی ثبت می‌شود؛ پنل‌های دیگر کپی جداگانه نمی‌سازند و از همان داده/رویداد دریافت می‌کنند.
کلیدهای داخلی دیتابیس حذف نشده‌اند و برای ارتباط داخلی استفاده می‌شوند؛ کاربر نیازی به واردکردن دستی شناسه ندارد.
